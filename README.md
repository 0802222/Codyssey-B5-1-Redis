# 정보를 엄청 빠르게 찾아주는 작은 저장소 만들기
## 과제 개요
이 과제는 `Redis` 를 이용해 정보를 빠르게 찾아주는 작은 저장소를 만드는 미션이다.

평소 레디스가 빠르다는건 알고있지만, 그 속에 있는 `HashMap`(빠른 Key-value 저장), `연결리스트` (LRU), `Heap`(TTL) 을 직접 만들어보면서 왜 빠른지 체감할 수 있는 미션이다.

### Redis란?
`Remote Dictionary Server` 의 줄임말로, 데이터를 DISK가 아니라 `MEMORY`(RAM)에 저장하는 저장소 이다.
| 구분 | 저장 위치 | 설명
| -- | -- | -- | 
| 일반 DB | 디스크 | 안정적이지만 느림 |
| Redis | 메모리 | 전원 꺼지면 휘발되지만 대신 훨씬 빠름 |

- 용도 : 캐시(자주 조회하는 데이터를 잠깐 저장해서 DB 부담 줄이기), 세션 저장, 실시간 랭킹 등에 사용


## 과제에서 사용되는 자료구조
### 1. HashMap (체이닝 방식)
- 정의 : Key를 숫자로 변환(Hash)해서 배열 칸에 `저장`하는 구조
- 위치 : 실제 데이터(Key-value)가 저장되는 메인 저장소
- 역할 : `SET` / `GET` 시 값을 즉시 찾아줌 (O(1))

### 2. 이중 연결 리스트
- 정의 : 노드들이 `Prev`(이전 노드 주소), `Next`(다음 노드 주소)를 서로 들고 있는 구조
- 위치 : LRU 순서를 관리하는 리스트 안에 존재 (해시맵의 체이닝에도 재사용)
- 역할 : `누가 제일 최근에 쓰였는지` 순서를 O(1)로 갱신

### 3. 최소 힙
- 정의 : 부모가 항상 자식보다 작은 값을 가지는 배열 기반 트리
- 역할 : `가장 먼저 만료될 Key`를 빠르게 찾음 (TTL 관리)
